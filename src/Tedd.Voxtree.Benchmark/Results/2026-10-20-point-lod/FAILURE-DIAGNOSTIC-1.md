# D1: fresh-session failure diagnostic with controller exceptions

Original P18 family stays failed/incomplete. Do not resume its plan, replace
sessions, finish its eighth case or pool new measurements with it. D1 is a new
task-owned catalog and a failure study, never promotion/performance evidence.
Existing catalogs, installed binaries and client settings stay unchanged.

Use the exact archived p18control/p18census bundles, runtime .NET 10.0.13 x64,
matching dependencies/runtime settings and the original eight version-12 point
scenarios. Verify current bundle bytes against the phase-seven manifest before
registration. Copy each original frozen experiment, with a new ID and seed
20261024; keep twelve paired blocks, 8,388,608 public reads, one warmup, 3-second
per-arm Prepare primes and 600-second per-plan budget. Total maximum 192 fresh
sessions, randomized arms, no extra sessions, exclusions or replacements. Stop
after the first failed/tainted/cancelled/interrupted operation; export what was
actually completed. No lab.compare, promotion decision or latency interpretation.

Competing causes: controller lifecycle/file cleanup, readiness/identity,
measurement/handshake, artifact/catalog write, or an external admission timeout.
Prediction: a reproduced generic failure should have a temporally bound first-
chance exception type/message, plus its accepted operation and launch/session
records. Multiple exceptions need chronology and source review; the first event
is not automatically causal. No failure within budget means unreproduced, not
proved fixed, safe or equivalent. A different explicit failure code is reported
separately. Preserve partial failures and never restart a tainted target.

Before D1, build a separate bounded exception recorder from installed diagnostic
libraries and self-test its actual record mode on the prior synthetic caught-
IOException child. Require marker, zero reported event loss, exact PID/start
binding, drained trace and joined exits. Use that same executable in D1.

Start one owned MCP controller, initialize it, then attach the recorder before
the first confirmation operation. Capture only that controller, matching its
kernel PID/start ticks. Targets retain their normal diagnostics-disabled launch
environment. Record raw trace/type/message/thread/time, up to 64 MiB/50,000
exception events/3300 seconds, with 16 MiB EventPipe buffer and no rundown.
Unexpected recorder exit ends further submissions after the current accepted
operation is polled to terminal. Stop/drain recorder before orderly controller
shutdown. Report missing/lost/truncated coverage; do not reinterpret it as zero.

Parent owns legacy pipeline admission; external setup uses the real central
mutex, released before controller-timed operations. Controller timed sessions
own that mutex internally. Recorder belongs to the admitted diagnostic process
group and adds observer work: D1 cannot supply quiet performance evidence.
All setup/launch/trace/SQLite/log/source files remain under the existing dedicated
task workspace. Startup is the already inspected offline voxel fixture only;
no game/server/world/database/deployment writes. Keep scoped supported grants
and accepted operation IDs; verify joined process identities before preservation.
