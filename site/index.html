One model, four operating layers

Move from voxels to worlds without changing representation.

Each layer has a narrow responsibility. Dense buffers support bulk work; octrees encode one channel; chunks group channels; worlds route and retain chunks.

A streamed world in a few explicit steps

Persist chunks. Bound residency. Load on demand.

Storage configuration is attached to the world. Dirty snapshots are written before release; reads load the addressed chunk when it is not resident.

  • Coordinate-safe. Negative global coordinates resolve through arithmetic shifts.
  • Format-aware. Chunk files carry codec, address, length, format version, and CRC32 metadata.
  • Policy-neutral. Your application controls generation, LOD selection, and unloaded-space semantics.

Choose the ownership contract

Owned convenience or caller-controlled memory.

Octree<T>Owns one final encoded byte array and supports lock-free replacement.
OctreeSpan<T>Reads validated caller-owned memory without copying or managed allocation.
HotOctreeChunk<T>Owns mutable dense Morton storage for an exclusive edit session.
OctreeWorld<T>Represents a bounded sparse region with explicit unloaded and known-empty states.

Operational boundaries

Storage mechanics are included. World policy remains yours.

Tedd.Voxtree does not generate LOD data, select an LOD, simulate entities, or infer whether unloaded space is air. Those decisions depend on the application.

WorldEntity is not thread-safe. Use its immutable published chunks within an application-defined synchronization model, or use OctreeWorld where its bounded, synchronized semantics fit.
